# Product traceability

This matrix tracks the canonical PRD in [`../design/MarketDesk PRD.dc.html`](../design/MarketDesk%20PRD.dc.html). Status describes the deployed product, not whether a route or component merely exists.

Status vocabulary:

- **Implemented** — original acceptance criteria are verified with code, tests and deployed evidence.
- **Partial** — a real subset works, but one or more acceptance criteria are missing.
- **Not implemented** — only a placeholder/mock exists or the capability is absent.
- **Docs only** — a product statement, not a runtime capability.

## Cross-cutting product decisions

| Decision | Runtime contract | Evidence | Tracking |
| --- | --- | --- | --- |
| Draft and below-cost pricing | Cost and selling price may be zero for incomplete drafts; negative prices are rejected. Selling below cost requires an explicit confirmation in create/edit UI and `allowBelowCost: true` at HTTP, application and domain boundaries. Approved Hermes recommendations provide an existing human-approval boundary; remote imports fail closed against known local cost. Accepted exceptions are included in product event payloads as `pricingDecision` audit evidence. Equal-to-cost needs no exception. No bulk-price mutation exists yet; any future bulk path must reuse this contract. | `Product.ts`, `ProductValidator.ts`, HTTP schemas, `ProductForm.tsx`, `ProductWizardForm.tsx`; domain/use-case/API boundary tests | Approved deviation in `PRODUCT.md`; [#177](https://github.com/ylazakovich/hermes-marketdesk/issues/177) |
| Architecture truth and review decisions | `ARCHITECTURE.md` is canonical and distinguishes implemented runtime contracts from accepted targets. Amendments are historical decisions only. Runtime scheduling uses Bull/Redis repeatable jobs; database evolution uses ordered idempotent SQL; Hermes uses the canonical seven-state persisted/API lifecycle with separate product labels. | `ARCHITECTURE.md` §§7, 10, 13; `ARCHITECTURE_AMENDMENTS.md`; migration runner, scheduler, `020_hermes_event_lifecycle.sql` and transition/API tests | Architecture consolidated by [#179](https://github.com/ylazakovich/hermes-marketdesk/issues/179); lifecycle delivered by [#178](https://github.com/ylazakovich/hermes-marketdesk/issues/178) |
| OLX exact-category and correction safety | Real publish requires current exact leaf metadata and rejects semantic contradictions. Preview/confirmation show provider ID and full path. Import/sync preserve provider metadata. Live mismatches create human-review recommendations plus separate persistent delist and recreate lifecycle records. Authenticated workspace routes approve and execute each operation independently; combined approval remains refused. Recreate reserves quota with `mode=recreate`, then consumes the reservation only after acquiring the shared publication fence and before the provider effect; unknown/stale/exhausted state is blocked unless its own persisted paid-risk override was approved. Delist records zero restored quota. Recreate shares the durable active-publication fence with publish/relist, preventing concurrent provider effects; retryable pre-provider quota denial returns the operation to approved. Advert lifetime is not quota availability. | `docs/olx-category-safety.md`; `CategoryCorrectionOperationService.ts`; `CategoryCorrectionOperationRepository.ts`; `OlxCategoryGuard.ts`; migrations `022_listing_marketplace_category.sql` through `026_validate_olx_publication_mode.sql`; authenticated Hermes routes | Category correction lifecycle/order/idempotency/override tests; authenticated route integration test; guard, publish, import, quota and adapter tests; [#169](https://github.com/ylazakovich/hermes-marketdesk/issues/169) |
| Sandbox mode and offline AI | While `OLX_ADAPTER_MODE=stub` (the default), OLX connects as a labelled sandbox account without OLX credentials: the connect action returns the app's success URL instead of an OLX authorization URL, marketplace views report `sandbox: true` for OLX, and a stored sandbox account is refused in real mode with a reconnect message. `HERMES_PROVIDER_MODE` (`auto`, `hermes` or `offline`, default `auto`) routes every AI call through `AIProviderSelector`: Hermes while it is configured and reachable, otherwise offline heuristics that say Hermes was not consulted and whose title, price and description changes are always held for review. Startup refuses a missing or placeholder `JWT_SECRET` or `MARKETPLACE_CREDENTIALS_KEY` and any `OLX_ADAPTER_MODE` other than `stub` or `real`, and `npm run env:init` generates the secrets. | `MarketplaceOAuthService.ts`, `MarketplaceController.ts`, `presenters.ts`, `container.ts`; `AIProviderSelector.ts`, `OfflineHeuristicAIProvider.ts`, `HermesHealthProbe.ts`, `HermesDecisionEngine.ts`; `assertStartupConfiguration` in `env.ts`; `scripts/init-env.mjs` | `MarketplaceOAuthService.test.ts` sandbox cases; API integration tests for sandbox connect and `GET /api/hermes/status`; `AIProviderSelector.test.ts`, `OfflineHeuristicAIProvider.test.ts`, `HermesHealthProbe.test.ts`, `HermesDecisionEngine.test.ts`; `env.test.ts`, `main.boot.test.ts`, `scripts/init-env.test.mjs`; approved deviation in `PRODUCT.md` (Sandbox mode); [#174](https://github.com/quokkify/marketdesk/issues/174) · [#139](https://github.com/quokkify/marketdesk/issues/139) |
